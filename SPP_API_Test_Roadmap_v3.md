# Дорожная карта автотестов API — SPP версия 5.3

## Общая информация

- **Документация:** SPP Описание API v5.3
- **Всего API методов:** 220
- **Расчётное количество тест-кейсов:** ~850
- **Приоритизация:** от критичных бизнес-процессов к вспомогательным
- **Базовый URL:** `https://<server>/api/web/v1/`
- **Формат данных:** JSON
- **Авторизация:** Bearer token (получается через методы 3.2 / 3.3)

---

## Подготовка к тестированию (обязательно перед стартом)

1. Получить доступ к тестовому окружению
2. Создать тестовых пользователей с разными ролями (Администратор, Оператор, Техподдержка)
3. Подготовить тестовые GTIN, коды маркировки (КМ), идентификаторы линий
4. Определить стратегию подготовки и очистки тестовых данных
5. Настроить переменные окружения: `base_url`, `admin_token`, `operator_token`

## Общие правила для всех тестов

1. **Всегда проверять** статус-код ответа (200, 4xx, 5xx)
2. **Всегда проверять** структуру тела ответа — наличие обязательных полей
3. **Всегда проверять** типы данных полей в ответе
4. **Для каждого метода** проверять запрос без авторизации (ожидать 401/403 для приватных)
5. **Для POST-методов** проверять запрос с пустым телом
6. **Для фильтрующих методов** проверять пагинацию (skip/limit)
7. **Тесты не должны зависеть** друг от друга — каждый создаёт нужные данные сам
8. **После теста** чистить созданные данные (teardown)
